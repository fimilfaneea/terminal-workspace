# Windows 11 Electron Terminal Workspace — v1 Plan (10 Phases)

A standalone Electron desktop terminal workspace at `apps/desktop`. Real PTY-backed panes, `cmd.exe` only, tabs and splits, runtime-only sessions, no cross-restart recovery. Not a chat app, not an agent UI.

This document supersedes all prior versions. The 10 phases below are sequential — each phase leaves the app in a working, manually-verifiable state that the next phase builds on.

---

## Locked decisions (read first)

| Area | Decision |
|---|---|
| Repo shape | Standalone npm project at `apps/desktop` (own `node_modules`, own `package-lock.json`). No workspace hoisting. |
| Stack | electron-vite + React 18 + TypeScript 5 (strict) + npm |
| Target | Windows 11 x64 only. ARM64, macOS, Linux are not supported. Dev shell may run on other OSes; sessions will fail. |
| Backend | `node-pty` in main only. `cmd.exe` only. conpty backend. |
| Frontend | xterm **6.x** with `@xterm/addon-fit`, `@xterm/addon-canvas`, `@xterm/addon-web-links`, `@xterm/addon-search`. Canvas renderer (not WebGL). |
| State | `zustand` for renderer workspace state. `electron-window-state` for window. `localStorage` for font size. Nothing else persisted across launches. |
| Splits | `react-resizable-panels` for splitter UI; our split tree state stays the source of truth. |
| Security | `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, CSP, `will-navigate` block, `setWindowOpenHandler` deny. |
| Preload | Three namespaces only — `window.terminal`, `window.shell`, `window.clipboard`. No generic IPC bridge. |
| IPC transport | `ipcRenderer.send` for `terminal:write` and `terminal:resize`. `ipcRenderer.invoke` for everything else. Internal `IpcResult<T>`; preload unwraps and rejects with `TerminalApiError`. |
| Close confirm | Native `dialog.showMessageBox` owned by main, triggered through `window:requestClose`. |
| Theme | Dark only (One Dark palette). |
| Single instance | `app.requestSingleInstanceLock()`. |
| Versioning | Exact pinned versions in `package.json`, no caret ranges. `package-lock.json` committed. |
| Tests | None in v1. Manual acceptance criteria per phase. |

# Phase 2 — Secure window, app shell, and persistence baseline

**Goal:** A single locked-down BrowserWindow with all required Electron security in place, single-instance lock, persisted window position, persisted global font size, suppressed application menu, and a `electron-log` channel ready for the rest of the app.

**Depends on:** Phase 1.

## 2.0 Phase 1 deviations carried forward

The Phase 1 scaffold deviates from the original plan in five places. Read these before touching anything, because some of them affect what files exist, what scripts run, and what versions you can assume.

1. **No `postinstall` hook in `package.json`.** The original spec ran `electron-builder install-app-deps` on install to rebuild `node-pty` from source against Electron's Node ABI. That forces a hard dependency on Visual Studio Build Tools (C++ workload) at install time, which was not available in the scaffold environment. `node-pty@1.1.0` ships N-API prebuilds for `win32-x64` that are ABI-stable across Electron versions, so the rebuild is redundant for the current dep set. The `rebuild:native` script (`electron-rebuild -f -w node-pty`) is retained for manual use if you bump Electron to a major where the bundled prebuilds no longer fit. **Action for Phase 2:** do not re-add the postinstall hook. If a future native dep is added that does not ship prebuilds, that is the moment to revisit — and document the VS Build Tools prerequisite in the README at the same time.

2. **`@xterm/addon-canvas` pinned to `0.8.0-beta.48` (not stable).** `@xterm/xterm@6.0.0` is locked by the plan, but the canvas addon's `latest` tag (`0.7.0`) still declares `peer @xterm/xterm@^5.0.0`. The 0.8 line is the xterm-6-compatible track but is currently only published as `beta`. **Action for Phase 2:** none — this only matters once xterm is wired up in Phase 5. When 0.8.0 stable ships, bump and drop the workaround in item 3.

3. **`.npmrc` contains `legacy-peer-deps=true`.** Even the 0.8 canvas beta still declares `peer @xterm/xterm@^5.0.0` (stale peer range upstream). The `.npmrc` keeps `npm install` working without requiring `--legacy-peer-deps` on every invocation. **Action for Phase 2:** leave as-is. Remove once both (a) `@xterm/addon-canvas` ships a stable 0.8 with a corrected peer range, and (b) any other dep added in later phases is peer-clean.

4. **`vite` and `@vitejs/plugin-react` are explicit devDependencies.** The original plan listed `electron-vite` but not `vite` or the React plugin. `electron-vite@5.0.0` declares `vite` as a peer (not a hard dep), and the renderer needs `@vitejs/plugin-react` to compile JSX. Pinned versions: `vite@7.3.2`, `@vitejs/plugin-react@5.2.0`. `vite@8` is the current latest, but `electron-vite@5` peer-caps at `vite@^7`, and `@vitejs/plugin-react@6` requires `vite@^8`, so both must stay on the 7.x / 5.x lines together. **Action for Phase 2:** treat these as part of the locked stack — do not bump independently.

5. **`electron.vite.config.ts` does not set explicit `build.outDir` or `rollupOptions.input` per target.** `electron-vite@5`'s stricter typings reject those literals on `MainBuildOptions`/`PreloadBuildOptions` even though the underlying Vite types accept them. The v5 defaults already produce `out/main`, `out/preload`, `out/renderer` and auto-resolve entries from `src/<target>/index.{ts,tsx,html}`, which matches what Phase 1 needed. **Action for Phase 2:** if you need to change outputs (you should not, for Phase 2), use the documented v5 surface — do not paste back the original spec's `build: { outDir, rollupOptions: { input } }` shape; it will not type-check.

## 3.3 `cmd.exe` resolution (in `spawn.ts`)

Try, in order, accepting the first that satisfies all three checks (`path.isAbsolute`, basename equals `cmd.exe` case-insensitively, `fs.existsSync`):

1. `process.env.COMSPEC`
2. `path.join(process.env.SystemRoot ?? 'C:\\Windows', 'System32', 'cmd.exe')`
3. `C:\\Windows\\System32\\cmd.exe`

If none pass, throw a typed error. Session creation will surface this as an errored pane (Phase 7).

## 3.4 Env filter (in `env.ts`)

```ts
export function filterEnv(input: NodeJS.ProcessEnv): Record<string, string> {
  const out: Record<string, string> = {};
  for (const [k, v] of Object.entries(input)) {
    if (v == null) continue;
    if (ENV_DENYLIST_PATTERNS.some((re) => re.test(k))) continue;
    out[k] = v;
  }
  return out;
}
```

`ENV_DENYLIST_PATTERNS` regexes are flagged `i` so matching is case-insensitive. The original key casing is preserved in `out`.

## 3.5 History ring buffer

```ts
export type HistoryChunk = { seq: number; data: string; createdAt: number };

export class History {
  private chunks: HistoryChunk[] = [];   // FIFO; deque-like usage with .shift()
  private bytes = 0;
  private lines = 0;

  append(chunk: HistoryChunk): void { /* push, update bytes/lines, evict */ }
  evict(): void { /* while over caps, shift oldest, decrement counters */ }
  clear(): void { /* zero everything */ }
  snapshotString(): { data: string; fromSeq: number; toSeq: number; truncated: boolean } { ... }
  get sizeBytes(): number { return this.bytes; }
  get sizeLines(): number { return this.lines; }
}
```

Line counting: count `\n` occurrences in `chunk.data`. Bytes counting: `Buffer.byteLength(chunk.data, 'utf8')`.

`truncated` flag in snapshot is true if any `evict()` has occurred since the last `clear()` (or session start).

# Phase 4 — Backend session operations, output batching, and lifecycle

**Goal:** Complete `TerminalManager` API surface — `write`, `resize`, `rename`, `restart`, `clearScrollback`, `snapshot`, `onEvent`, `closeAll` — plus output batching with sequencing and synthetic exit messages. Still no IPC; verify via the debug harness.

**Depends on:** Phase 3.

## 4.1 Session methods (in `TerminalSession`)

- `write(data: string)` — `pty?.write(data)`. Bumps `updatedAt`.
- `resize(cols, rows)` — `pty?.resize(cols, rows)`. Updates session record only when cols/rows actually change.
- `rename(title: string)` — sets title; emits `renamed` event. Empty strings rejected by caller, not here.
- `restart()` — kills current pty (graceful kill, ≤ 1500 ms wait, force-kill), clears history, resets `outputSeq` to 0, clears `pid/exitCode/exitSignal`, updates `createdAt`, then spawns again with the same spawn cwd. Emits `started` (or `error` on failure → status `'errored'`).
- `clearScrollback()` — calls `history.clear()`, emits `cleared`. **Does not reset `outputSeq`.** PTY keeps running.
- `snapshot()` — returns `{ sessionId, fromSeq, toSeq, data, truncated }` from `history.snapshotString()`.
- `close()` — graceful kill, on exit emits `closed`.

## 4.2 Output batching

In `TerminalSession`'s pty `onData` handler:

```ts
onData(chunk):
  pendingOutput.push(chunk)
  pendingBytes += byteLength(chunk)
  if pendingBytes >= FLUSH_MAX_BYTES:
    flush()
  else if !flushTimer:
    flushTimer = setTimeout(flush, FLUSH_INTERVAL_MS)
```

`flush()`:

1. Join `pendingOutput` into one string.
2. Reset `pendingOutput`, `pendingBytes`, clear `flushTimer`.
3. Increment `outputSeq`.
4. Append `{ seq: outputSeq, data, createdAt: Date.now() }` to history.
5. Emit `output` event `{ sessionId, seq, data }` via the manager's event bus.

Edge: if `close()` or `restart()` is called with a pending flush, run `flush()` synchronously first so no output is lost.

## 4.3 Exit handling

`pty.onExit({ exitCode, signal })`:

1. Run any pending flush.
2. Inject a synthetic chunk: `\r\n[Process exited with code N]\r\n` (use `signal` if no `exitCode`). This goes through the same flush path so it has a real `seq`, joins history, and is replayed by snapshot.
3. Set `status = 'exited'`, store `exitCode` / `exitSignal`.
4. Emit `exited`.

## 4.4 Event bus

```ts
type TerminalEvent =
  | { kind: 'started'; sessionId: string; info: SessionInfo }
  | { kind: 'output'; sessionId: string; seq: number; data: string }
  | { kind: 'exited'; sessionId: string; exitCode: number | null; exitSignal: string | null }
  | { kind: 'error'; sessionId: string; message: string; code?: string }
  | { kind: 'closed'; sessionId: string }
  | { kind: 'renamed'; sessionId: string; title: string }
  | { kind: 'cleared'; sessionId: string };

class TerminalManager {
  onEvent(listener: (e: TerminalEvent) => void): () => void
}
```

Implement as a small in-house emitter (Set of listeners; `onEvent` returns an unsubscribe). Sessions push events through a manager-provided callback so listeners get a single stream covering all sessions.

## 4.5 `closeAll(timeoutMs)`

```ts
async closeAll(timeoutMs = TERMINAL_SHUTDOWN_TIMEOUT_MS) {
  const all = [...this.sessions.values()];
  // start graceful kill on every session in parallel
  // race Promise.allSettled([...gracefulCloses]) against setTimeout(timeoutMs)
  // for any session still running at timeout, call pty.kill('SIGKILL')
  // then await all once more with a short tail timeout
  this.sessions.clear();
}
```

## 4.6 Snapshot semantics tightening

`outputSeq` is monotonic per session and resets only on `restart()`, never on `clearScrollback()`. After `clearScrollback()`, the next emitted `output` event will have a `seq` strictly greater than any prior `seq` for that session, but the history will be empty. Renderer must therefore handle the `cleared` event separately from snapshot replay.

## 4.7 Debug harness expansion

Extend the gated debug harness from Phase 3 to:

1. Create a session and subscribe via `onEvent`.
2. Write `dir\r\n`.
3. Verify `output` events arrive with monotonic `seq`.
4. Call `clearScrollback()`. Verify `cleared` event and snapshot returns empty data with `seq` unchanged.
5. Call `restart()`. Verify `started` event and snapshot data is empty with `fromSeq = 1`.
6. Call `close()`. Verify `exited` then `closed`.
7. Call `closeAll()` with one extra unkilled session and a forced infinite loop (`type CON`) to verify the timeout/force path.

## 4.8 Acceptance criteria

- Writing `dir\r\n` produces output that arrives within ~12 ms in batched events.
- Bursting 1 MB of synthetic output causes flushes triggered by the byte cap, not the timer.
- After `clearScrollback()`, a fresh snapshot has empty data but the next output event's `seq` is greater than any prior `seq`.
- After `restart()`, snapshot is empty, `seq` starts at 1, title and spawn cwd are unchanged, pid is new.
- A session whose child loops infinitely is force-killed within ~1.5 s of `closeAll()`.
- Closing while a flush is pending does not lose output (the synthetic exit chunk is preserved).
- Resize with unchanged cols/rows does not bump `updatedAt`.

## 5.3 `IpcResult<T>` internal shape

```ts
type IpcResult<T> =
  | { ok: true; value: T }
  | { ok: false; message: string; code?: string };
```

Every `invoke` handler in main wraps its body:

```ts
ipcMain.handle('terminal:create', async (_e, payload): Promise<IpcResult<SessionInfo>> => {
  try {
    const info = manager.create(payload);
    return { ok: true, value: info };
  } catch (err) {
    log.error('terminal:create failed', err);
    return { ok: false, message: errorMessage(err), code: errorCode(err) };
  }
});
```

## 5.4 `TerminalApiError` and preload unwrap

```ts
export class TerminalApiError extends Error {
  code?: string;
  constructor(message: string, code?: string) {
    super(message);
    this.name = 'TerminalApiError';
    this.code = code;
  }
}

async function callInvoke<T>(channel: string, payload: unknown): Promise<T> {
  const result = (await ipcRenderer.invoke(channel, payload)) as IpcResult<T>;
  if (result.ok) return result.value;
  throw new TerminalApiError(result.message, result.code);
}
```

Preload wraps every invoke in `callInvoke` so renderer code uses normal awaited promises.

## 5.5 `window.terminal` API (preload)

```ts
contextBridge.exposeInMainWorld('terminal', {
  create: (opts) => callInvoke('terminal:create', opts),

  resize: (sessionId, cols, rows) => ipcRenderer.send('terminal:resize', { sessionId, cols, rows }),

  rename: (sessionId, title) => callInvoke('terminal:rename', { sessionId, title }),

    const handler = (_e, evt) => listener(evt);
```

## 6.5 `applyTerminalEvent`

```ts
switch (evt.kind) {
  case 'started':
    sessionsById[evt.sessionId] = { info: evt.info, hasUnreadActivity: false };
    break;
  case 'output':
    // bump unread on inactive tabs (Phase 8 visualises it)
    if (paneIsInBackgroundTab(evt.sessionId)) {
      sessionsById[evt.sessionId].hasUnreadActivity = true;
      tab.hasUnreadActivity = true;
    }
    break;
  case 'exited':
    sessionsById[evt.sessionId].info = { ...info, status: 'exited', exitCode, exitSignal };
    break;
  case 'error':
    sessionsById[evt.sessionId].info.status = 'errored';
    tab.hasError = true;
    break;
  case 'renamed':
    sessionsById[evt.sessionId].info.title = evt.title;
    break;
  case 'cleared':
    // no store change; the pane component listens directly and calls term.clear()
    break;
  case 'closed':
    delete sessionsById[evt.sessionId];   // pane removal handled separately
    break;
}
```

```ts
useEffect(() => {
```

| Paste | `Ctrl+Shift+V` | (Phase 9) |
| Find | `Ctrl+Shift+F` | (Phase 9) |
| Font + / − / 0 | `Ctrl+= / Ctrl+- / Ctrl+0` | (Phase 9) |

`Ctrl+C`, `Ctrl+V`, `Ctrl+Z`, `Ctrl+A`, `Ctrl+L`, `Tab`, `ArrowUp/Down/Left/Right`, `Home`, `End`, `PageUp`, `PageDown`, `Alt+Enter`, all function keys.

- `Esc` → revert and exit edit mode.
- `Blur` → save (same as Enter) unless empty (revert).
- Used by:
  - Tab bar: editing renames the **session of the tab's focused pane**.
  - Pane header: editing renames the **pane's session**.

`Ctrl+Shift+R` (from Phase 8) opens edit mode on the focused pane's title.

`onRename` calls `renameSession(sessionId, title)`, which calls `window.terminal.rename`. Success bumps the title via the `renamed` event.

## 9.3 Right-click context menu

`<ContextMenu>` is mounted on the pane container at `oncontextmenu`. Suppresses the default browser menu.

Items:

- **Copy** — disabled if no selection. `term.getSelection()` → `window.clipboard.writeText(...)`.
- **Paste** — runs the paste flow (9.6).
- **Clear scrollback** — `window.terminal.clearScrollback(sessionId)`. Backend emits `cleared`; pane calls `term.clear()`.
- **Find** — opens the FindBar.
- **Rename** — opens RenamableTitle in edit mode.
- **Restart** — `window.terminal.restart(sessionId)`.
- **Close pane** — `closePane(paneId)` (routes to `window:requestClose` if last; Phase 10).

Items are keyboard-navigable with arrow keys, `Enter` activates, `Esc` closes. Click outside also closes.

## 9.4 Find bar

`<FindBar>` overlays the top-right of a pane:

- Text input.
- `Next` (`Enter` or down-arrow), `Prev` (`Shift+Enter` or up-arrow).
- Case-sensitive toggle.
- Regex toggle.
- `Esc` closes.

Wired to `SearchAddon`:

```ts
search.findNext(query, { caseSensitive, regex });
search.findPrevious(query, { caseSensitive, regex });
```

`Ctrl+Shift+F` opens the find bar on the focused pane.

## 9.5 Copy

`Ctrl+Shift+C` and context-menu Copy:

```ts
const sel = term.getSelection();
if (!sel) return;                              // no-op when nothing selected
await window.clipboard.writeText(sel);
```

Selection is preserved after copy.

## 9.6 Paste with safety

`Ctrl+Shift+V` and context-menu Paste:

```ts
const text = await window.clipboard.readText();
if (text.length === 0) return;
const bytes = new TextEncoder().encode(text).length;
if (text.includes('\n') && bytes > PASTE_CONFIRM_BYTE_THRESHOLD) {   // 1024
  showPasteConfirm({
    lines: countLines(text),
    bytes,
    onConfirm: () => window.terminal.write(sessionId, text),
  });
} else {
  window.terminal.write(sessionId, text);
}
```

`PasteConfirmDialog` is a renderer modal (not native — renderer is healthy in this path):

> Paste **N lines** (X bytes) into terminal?
> [ Cancel ] [ Paste ]

`Esc` cancels. `Enter` confirms. Focus is trapped in the dialog while it's open.

## 9.7 Global font zoom

Bound shortcuts:

- `Ctrl+=` → `bumpFontSize(+1)` (clamped to `MAX_FONT_SIZE_PX`).
- `Ctrl+-` → `bumpFontSize(-1)` (clamped to `MIN_FONT_SIZE_PX`).
- `Ctrl+0` → `resetFontSize()` (back to `DEFAULT_FONT_SIZE_PX = 13`).

The store's `fontSizePx` is reactive; every mounted `TerminalPane` re-applies `term.options.fontSize` and runs `fit.fit()`. Persistence is debounced via `usePersistedFontSize`.

## 9.8 Accessibility minimums

- All buttons have visible focus rings.
- Context menu items are reachable via keyboard.
- Modal dialogs trap focus and are dismissable with `Esc`.
- The terminal pane itself is a focusable region (xterm handles its own focus).

## 9.9 Acceptance criteria

- Double-click a tab title or pane header → inline edit; Enter saves; Esc cancels; blur saves; empty rejected.
- `Ctrl+Shift+R` opens rename on the focused pane's title.
- Right-click on a pane shows the menu with the seven items; each works.
- "Clear scrollback" wipes the pane but the cmd.exe prompt continues working; new output starts at the next sequence number.
- `Ctrl+Shift+F` opens find; typing finds matches; case and regex toggles affect results; Esc closes.
- Selecting text and `Ctrl+Shift+C` puts text on the system clipboard.
- `Ctrl+Shift+V` pastes from clipboard; pasting "hello" silently writes; pasting a 5 KB multi-line script triggers the confirm.
- Cancelling the paste confirm writes nothing.
- `Ctrl+=`, `Ctrl+-`, `Ctrl+0` adjust font size for ALL panes globally; reload preserves last value.

## 10.2 Native close-confirm dialog

In `src/main/dialogs.ts`:

```ts
export async function showCloseConfirm(
  win: BrowserWindow,
  runningCount: number,
): Promise<boolean> {
  if (runningCount === 0) return true;
  const { response } = await dialog.showMessageBox(win, {
    type: 'warning',
    buttons: ['Close all', 'Cancel'],
    defaultId: 1,
    cancelId: 1,
    title: 'Terminal Workspace',
    message: `${runningCount} terminal${runningCount === 1 ? '' : 's'} still running. Close anyway?`,
  });
  return response === 0;
}
```

Native dialog, modal to the window. Works even if the renderer is hung.

## 10.3 `window:requestClose` IPC

The renderer never closes the window itself. Instead, any path that would destroy the last surviving pane calls `window:requestClose`. Main:

1. Counts sessions with `status === 'running'` via `manager.list()`.
2. Calls `showCloseConfirm(win, count)`.
3. If `false`, returns; the workspace stays as-is (the renderer treats this as a cancel and does nothing).
4. If `true`, calls `proceedToQuit()`:
   - Stop accepting new IPC requests (set a `shuttingDown` flag in each handler that rejects with code `'shutting_down'`).
   - `await manager.closeAll(TERMINAL_SHUTDOWN_TIMEOUT_MS)`.
   - `app.quit()`.

## 10.4 Window close button

`win.on('close', (e) => { ... })` intercepts the OS close. Same flow:

```ts
let confirmedQuit = false;
win.on('close', async (e) => {
  if (confirmedQuit) return;
  e.preventDefault();
  const ok = await showCloseConfirm(win, manager.runningCount());
  if (!ok) return;
  confirmedQuit = true;
  await proceedToQuit();
  win.destroy();
});
```

`proceedToQuit` is idempotent. If called twice, the second call is a no-op.

## 10.5 Renderer routing

In Phase 8/9, `closeTab` and `closePane` returned `{ wouldCloseWindow }`. The shortcut and UI handlers now check that flag:

```ts
const result = await closeTab(activeTabId);
if (result.wouldCloseWindow) {
  await callInvoke('window:requestClose', {});
  // main handles confirmation + closeAll + quit
}
```

The same applies to `closePane` on the last surviving pane.

This means there is exactly **one** confirmation path in the entire app, owned by main, used by:

- OS window close button.
- `Ctrl+Shift+W` on the last tab.
- `Ctrl+Shift+X` on the last pane in the last tab.
- The `×` close-tab button on the last tab.

No `CloseConfirmDialog.tsx` exists in the renderer.

## 10.6 Graceful shutdown semantics

`manager.closeAll(timeoutMs)`:

```ts
async closeAll(timeoutMs = TERMINAL_SHUTDOWN_TIMEOUT_MS) {
  this.shuttingDown = true;
  const sessions = [...this.sessions.values()];
  // Start graceful kill on all in parallel
  for (const s of sessions) s.beginGracefulClose();
  // Wait, racing all-settled vs timeout
  await Promise.race([
    Promise.allSettled(sessions.map((s) => s.waitUntilExited())),
    delay(timeoutMs),
  ]);
  // Force-kill survivors
  for (const s of sessions) {
    if (s.getInfo().status === 'running') s.forceKill();
  }
  // Brief tail wait
  await Promise.race([
    Promise.allSettled(sessions.map((s) => s.waitUntilExited())),
    delay(500),
  ]);
  this.sessions.clear();
}
```

Idempotent. Safe to call multiple times.

## 10.7 Dev-mode reload cleanup

Renderer reloads (HMR full-page or manual refresh) would otherwise leave PTYs orphaned (renderer state dies but main keeps the sessions). Wire:

```ts
let firstLoad = true;
win.webContents.on('did-start-loading', () => {
  if (firstLoad) { firstLoad = false; return; }
  // Synchronously close all sessions before the new renderer mounts
  void manager.closeAll(500);    // shorter timeout in dev
});
```

This makes dev parity with production: every renderer load starts with a fresh workspace and zero PTYs.

## 10.8 IPC `shuttingDown` gate

Every `invoke` handler checks the flag at the top:

```ts
if (manager.shuttingDown) {
  return { ok: false, message: 'Application is shutting down', code: 'shutting_down' };
}
```

`send` handlers (`terminal:write`, `terminal:resize`) silently drop while shutting down.
